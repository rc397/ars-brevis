## 2026-07-07

Scaffolded the repository. The harness lives in `brevis/` with a subprocess sandbox, a byte-count scorer, and an eval entrypoint. A solution is one Python file defining `p(grid)` and scores by file size in bytes. Vendored the 400 public ARC-AGI-1 training tasks from fchollet/ARC-AGI through `scripts/fetch_arc.py` and kept their Apache 2.0 license next to the data. Added an identity fixture task and a 12 byte example solution. The smoke test and the eval CLI both pass end to end. The gold directory is gitignored apart from its README and will hold the private 2025 comp solutions. Next up is importing those for the human par line, then a hidden-test generator so hardcoded outputs cannot pass.

Added CLAUDE.md and PLAN.md so any session rooted in this repo carries the full plan, the style rules and the git identity without depending on another project's memory.

Built the generated task pipeline and the score entrypoint. Seventeen families in `brevis/families.py` cover grid ops, row ops and a little number theory, and `scripts/gen_tasks.py` renders 31 tasks into `data/generated/tasks` from a manifest plus a seed. The manifest pins each task's parameters while the seed drives the pairs, so a private seed produces hidden pairs for the same task ids and a hardcoding solution fails them. A guard test proves that end to end. `python -m brevis file.py` now scores a single solution and resolves the task by filename. Property tests cover every family and edge tests cover the sandbox and scorer. Filled `examples/solutions` with 29 golfed training-task solutions at 1361 bytes plus three generated-task solutions at 116. The gold import and the par run still wait on the 2025 archive.

Added the phase two scaffolding. `scripts/eval_model.py` samples any model command best of k against the harness, keeps the shortest passing program per task and writes `results.json` under `runs/`. The prompt template is fixed in `brevis/sampler.py` and shows train pairs only. `scripts/claude_cmd.py` wraps the Claude API behind the same stdin to stdout interface and `scripts/leaderboard.py` renders runs as a table. Sampler tests drive the loop end to end with stub models and a CI workflow now runs the tests on Linux and Windows.

## 2026-07-08

Closed phase one. Imported the 2025 comp archive from `C:\Arc_golf` and recorded the human par line. `scripts/import_gold.py` maps all 400 Google Code Golf 2025 tasks onto the ARC training ids by matching train pairs, then pools every `taskNNN.py` across every submission folder and zip into one candidate set per task. It ignores folder names and dates entirely, since later versions are sometimes longer or broken. Each candidate is re-verified in our sandbox and the shortest passing one wins, so a regressed version loses on bytes and a broken one is skipped. All 400 tasks imported with a verified solution and no gaps. `scripts/record_par.py` re-scores the gold set through the standard eval and writes byte counts only to `data/par.json`, never the solutions. The par line is 400 of 400 at 131663 bytes, a mean near 329 bytes per task. `scripts/leaderboard.py` now carries a human par row.

Started local model evaluation through Ollama. qwen2.5 7b solved zero of the 31 generated tasks, inventing wrong rules on even the mirror task, which is a genuine capability floor. Added a `--keep` flag to save raw completions for failure analysis. Qwen3-4B, the model the plan names first, does markedly better at 9 of 31 best of two. It reliably golfs the geometric tasks like rotation, transpose, tiling and scaling but misses the reasoning tasks like prime detection and gravity.

Two findings worth recording. At best of two the per-run solve set is noisy. An earlier partial run solved border, mirror and modsum where the final run failed them and vice versa, so a single low k run understates the model and the leaderboard needs a higher k or a proper pass at k before the numbers are stable. And a byte sum across entries only means something on a shared task set over the same solved tasks, since a model that solves nine tasks and a baseline that solves thirty one are not comparable by total bytes. `scripts/leaderboard.py` now ranks by solve rate and prints that caveat. To give the generated set a real golf baseline, `examples/solutions` now carries a verified solver for all 31 generated tasks at 1755 bytes alongside the 29 ARC samples.
